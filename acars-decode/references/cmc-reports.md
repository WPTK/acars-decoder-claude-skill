# CMC / Maintenance Report Decode Reference

## Overview

CMC (Central Maintenance Computer) reports are ACARS messages generated by onboard maintenance computers when faults, events, or status conditions are detected. They arrive as Label H1 messages (sublabel CF) or as standalone reports with identifiable RPT/Line structure.

Report format varies by manufacturer. This reference covers Boeing, with placeholders for Airbus and Embraer as examples are collected.

---

## Boeing CMC Report Structure

### General format
```
Line A: RPTxx PGn  <fault/system description> <REAL/TEST/FAULT>
Line B: .TAILNUM DDMMMYY HHMM CALLSIGN  ORIGIN/DEST CMC-xxx ENGINE-xxx  ER/FR
Line R: +DDMMSS  -DDDMMSS  FLxxx  +weight  temp  groundspeed
Lines 1-6: System-specific status readouts
Line 7: Timestamp (DDMMMYY HH:MM:SS)
Line 8: Additional data (if present)
```

### Line A — Report identification
- **RPTxx**: Report type number. The number corresponds to the system/ATA chapter being reported.
- **PGn**: Page number (PG1, PG2, etc.) — multi-page reports split across pages
- **Description**: Plain-text fault or system description
- **Status**: 
  - `REAL` — Genuine event detected (operationally significant)
  - `TEST` — System test triggered the report
  - `FAULT` — System fault detected
  - `MAINT` — Maintenance-related

### Line B — Flight and aircraft identification
| Field | Description |
|-------|-------------|
| `.TAILNUM` | Aircraft registration (dot prefix) |
| `DDMMMYY` | Date (e.g., 01APR26 = April 1, 2026) |
| `HHMM` | Time UTC |
| `CALLSIGN` | ICAO flight number (e.g., GTI8701, DAL1234) |
| `ORIGIN/DEST` | ICAO airport codes for origin and destination |
| `CMC-xxx` | CMC software load version |
| `ENGINE-xxx` | Engine type software identifier |
| `ER` or `FR` | Report type: ER = Event Report, FR = Fault Report |

### Engine type identifiers (from Line B)
| Code | Engine type | Typical aircraft |
|------|-------------|-----------------|
| `GE-805` | GEnx-2B67 | 747-8F/8i |
| `GE-8xx` | GE/GEnx variants | 787, 747-8 |
| `CF-xxx` | CFM56 variants | 737NG, A320ceo |
| `LF-xxx` | LEAP-1B | 737 MAX |
| `LA-xxx` | LEAP-1A | A320neo |
| `PW-xxx` | PW4000 variants | 767, 777, 747-400 |
| `GP-xxx` | GP7200 | A380 |
| `RR-xxx` | Rolls-Royce Trent | 787, A350, A380 |
| `GE-9xx` | GE90 | 777 |

### Line R — Position at time of event
| Field | Format | Description |
|-------|--------|-------------|
| Latitude | `+DDMMSS` or `-DDMMSS` | + = North, - = South. Degrees, minutes, seconds |
| Longitude | `+DDDMMSS` or `-DDDMMSS` | + = East, - = West. Degrees, minutes, seconds |
| Flight level | 3 digits | Multiply by 100 for feet (e.g., 255 = FL255 = 25,500 ft) |
| Gross weight | `+nnnnn` | Weight in tens of pounds (e.g., +39977 = ~399,770 lbs) |
| OAT | Signed number | Outside air temperature in °C |
| Ground speed | 3 digits | Knots |

**Position conversion**: To convert Line R lat/lon to decimal degrees:
- `+294504` = 29°45'04"N = 29 + 45/60 + 04/3600 = 29.751°N
- `-0832050` = 083°20'50"W = -(83 + 20/60 + 50/3600) = -83.347°W

### Lines 1–6 — System-specific status

These lines vary entirely by RPT number and ATA chapter. Common patterns:

**RPT42 (Cargo fire system, ATA 26):**
Lines 1-6 show detector loop and fire bottle status for cargo compartments.
- `NORM` = normal/healthy
- Numeric values or fault codes indicate sensor readings or failures
- Multiple columns correspond to different zones/loops

**Engine reports (RPT01-09, ATA 71-80):**
Lines show engine parameter snapshots: N1, N2, EGT, fuel flow, oil pressure/temp, vibration levels.

**Flight control reports (RPT10-19, ATA 27):**
Lines show actuator positions, FCPC (Flight Control Primary Computer) status, surface positions.

**Hydraulic/pneumatic (RPT20-29, ATA 29/36):**
Lines show system pressure, quantity, pump status, valve positions.

### Line 7 — Precise timestamp
Format: `DDMMMYY HH:MM:SS` (e.g., `01APR26 05:33:36`)

## Airbus CMS (Centralized Maintenance System) Reports

*This section will be expanded as examples are collected.*

Airbus uses CFDS (Centralized Fault Display System) and CMS rather than "CMC." Key differences from Boeing:

### Expected structure
- **POST REPORT** or **FAULT MESSAGE** header
- **ATA chapter** (2-digit) + **fault code** (4-digit)
- **ECAM message** correlation (what the crew saw on the Electronic Centralized Aircraft Monitor)
- **LRU identification** (Line Replaceable Unit — the specific box/component)
- **Flight phase** at time of fault
- **CMS class**: Class 1 (confirmed fault), Class 2 (intermittent), Class 3 (informational)
- Position and flight data similar to Boeing but formatted differently

### Airbus ATA chapter references
Same ATA 100 chapter system as Boeing. Common Airbus-specific reports:
- ATA 21 (Air conditioning/pressurization) — pack faults
- ATA 22 (Auto flight) — AP/FD/ATHR faults
- ATA 24 (Electrical) — generator/bus faults
- ATA 27 (Flight controls) — ELAC/SEC/FAC faults
- ATA 31 (Indicating/recording) — ECAM/display faults
- ATA 32 (Landing gear) — LGCIU faults
- ATA 34 (Navigation) — ADIRU/GPS faults
